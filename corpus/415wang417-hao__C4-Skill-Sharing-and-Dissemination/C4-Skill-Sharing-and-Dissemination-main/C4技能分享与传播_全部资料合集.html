Challenge 4：技能分享与传播（Skill Sharing & Propagation）

🔥 这是整个 Elite20 体系最关键的挑战。
本质是：把个人能力 → 可复制的 Agent Skill → 被他人使用 → 自我迭代优化。

一、挑战目标

每个学生提供一个明确、可复用的技能（Skill），教会别人如何使用，让别人真正用起来。

不是写一篇教程，不是分享一个 tip——而是交付一个可安装、可执行、可验证的技能包，附带完整的使用说明和真实案例。

二、技能四条件

你提交的技能必须同时满足以下四个条件：

条件含义检验方法
可复用（Reusable）别人拿过去能直接用，不依赖你的特定环境让一个陌生人按你的说明操作，能成功吗？
可执行（Executable）不是理论，是能跑的东西有可运行的 prompt / 代码 / workflow
可验证（Verifiable）有明确的输入输出，能判断成功与否给定输入 X，能得到预期输出 Y 吗？
IO 明确（Clear I/O）输入什么、输出什么，一目了然一句话能说清"输入____，输出____"

三、技能类型（任选方向）

类型示例
Prompt / AI Skill高级 prompt 模板、agent workflow、CLAUDE.md / skill.md
技术技能Claude Code 使用套路、自动化脚本、数据分析 pipeline
生产力技能用 AI 写论文、做 PPT、做营销
业务技能招标书生成、用户调研自动化、产品设计流程

你不需要会编程。"用 AI 做高质量 PPT 的完整流程"也是一个技能，只要别人能拿着你的说明复现出来。

四、必须提交的内容

文件命名格式说明
Skill 说明文档姓名_C4_skill说明.md解决什么问题、使用场景、输入输出、使用步骤、真实案例
可执行内容姓名_C4_技能名.skill 或 .py 或 .md可安装的 .skill 包 / prompt / 代码 / workflow
Demo姓名_C4_demo.mp4 或截图视频、截图、或 live demo
教学说明姓名_C4_教学说明.md如何上手、常见坑、优化技巧——关键是教别人用
⚡ AI 日志姓名_C4_AI日志.md用了什么 AI、怎么指挥的、迭代了几轮、你做了什么

五、评判标准

权重指标说明
🥇 最高被使用次数有多少人实际用过你的技能？是否产生了结果？
🥈 次要使用效果反馈别人用了觉得怎么样？
🥈 次要复用性 / 易用性拿过去能不能直接用？上手难不难？

🏆 前三名直接录取 Elite20。

注意：不是谁的技能"最厉害"谁赢——而是谁的技能被最多人用了。一个简单但人人都用的技能，胜过一个复杂但没人碰的技能。

六、群内传播机制（核心）

提交技能只是开始，真正的价值在传播链：

发布技能到群 → 别人提问 → 你回答/帮助 → 别人成功使用 → 反馈改进 → 你迭代 v2

这个循环跑得越快、覆盖人越多，你的 C4 分数越高。同时也自动为你的 C3（高质量参与）和 C7（内容传播）加分。

七、技能包的结构（.skill 文件标准）

一个 Claude Skill 包的标准结构如下：

技能名/
├── SKILL.md              （必须）主指令文件
│   ├── YAML frontmatter   → name + description（触发入口）
│   └── Markdown body      → 工作流程、步骤、代码、示例、边界情况
├── scripts/              （可选）可执行脚本
│   └── xxx.py             → 确定性/重复性任务用脚本
├── references/           （可选）参考资料
│   └── xxx.yaml / .md     → 按需加载的文档
└── assets/               （可选）模板、图标、字体

三层加载机制：

  1. 元数据（name + description）— 始终在上下文中，决定是否触发（约100词）
  2. SKILL.md 正文 — 触发时加载（理想 < 500 行）
  3. 附属资源 — 按需加载（无限制，脚本可不加载直接执行）

打包后的 .skill 文件就是一个 tar.gz 压缩包，可以直接安装到 Claude 环境中。

八、两个示例技能详解

以下是本次对话中实际创建的两个真实技能，作为 C4 提交的参考样板。两个 .skill 文件已附在本文档同一群消息中，可直接下载安装使用。

示例 1：wechat-doc-mapper（微信文档挑战映射器）
一句话说明

输入一个微信同步文件夹路径，输出按作者×挑战分组的文档清单表 + Excel 文件 + 缺口分析。

解决什么问题

Elite20 群里大家往群里扔文件，但没人知道：谁交了什么？哪个挑战还缺什么？哪些文件没有按规范命名？手动整理费时费力，而且容易漏。

这个技能自动化了整个盘点流程：扫描 → 识别作者 → 识别格式和标题 → 推断用途 → 映射到挑战 → 生成报告。

技能架构
wechat-doc-mapper/
├── SKILL.md                          （主指令，322 行）
│   ├── 前置条件：命名规范 + 回退提取链
│   ├── 6 步工作流：路径 → 作者识别 → 盘点 → 标题提取 → 挑战映射 → 输出
│   └── 边界情况：空文件夹、超大文件、编码问题、命名不规范等
├── scripts/
│   └── wechat_doc_mapper.py          （19.4 KB — 扫描器 + 映射器 + Excel 生成器）
└── references/
    └── challenges.yaml               （C1–C7 挑战注册表，含信号关键词）
核心设计
  1. 作者优先：先识别谁提交的（从文件名规范 → PDF/DOCX 元数据 → 文件夹名 → 文档开头），再分析内容。就像收作业——先看名字，再看内容。
  1. 信号评分映射：每个挑战在 YAML 中定义了关键词（如 C4 的 skill、agent、workflow）、扩展名（如 .skill）、路径片段（如 /demo/）。脚本对每个文件计算多维信号分数，自动分配主挑战和副挑战。
  1. 缺口分析：对比每个作者的提交和挑战的"预期产出物清单"，自动报告缺了什么。例如："LiMing 的 C2 缺少 references.bib 和 summary.md"。
  1. 双格式输出：Markdown 表格（在聊天中直接显示）+ 4 页 Excel（文档清单、作者×挑战矩阵、缺口分析、挑战参考）。
使用方式

安装 .skill 文件后，对 Claude 说：

"扫描 ~/Documents/WeChat Files/Elite20群，把所有文件映射到挑战上"

或英文：

"Scan this folder and map documents to challenges: /path/to/folder"

示例 2：skill-explainer（技能 X 光分析器）
一句话说明

输入任意一个 .skill 文件或技能目录，输出一份结构化的 Markdown 分析报告，涵盖用途、架构、用法、评审和改进建议。

解决什么问题

当你拿到一个别人写的 skill，你怎么知道它是干什么的？写得好不好？能不能用？有没有坑？

手动读 SKILL.md 可以，但你可能漏掉：描述质量差导致不会被触发、缺少边界情况处理、目录结构不规范、假设了不存在的前置知识……

这个元技能像一个"技能评审员"：系统性地拆解技能的每一层，用一套标准化的评审维度（D1–D4）打分，并给出具体可操作的改进建议。

技能架构
skill-explainer/
├── SKILL.md                          （主指令，231 行）
│   ├── 4 步工作流：解析 → 扫描目录 → 分析 → 生成报告
│   ├── 7 节报告模板（身份、用途、架构、参考、用法、评审、建议）
│   └── 边界情况：空 SKILL.md、无 frontmatter、超长文件、损坏的 .skill 包等
└── references/
    └── rubric.md                     （评审维度标准 D1–D4，含评分表和常见陷阱）
核心设计
  1. 纯指令技能：没有脚本——它教 LLM 如何分析，而不是用代码分析。这本身就展示了技能的两种形态：指令驱动 vs 脚本驱动。
  1. 四维评审矩阵（来自 references/rubric.md）：
维度权重评什么
D1 描述质量高触发短语够不够多？中英文都有吗？够"主动"吗？
D2 结构完整性高有没有清晰的工作流？有没有示例？有没有边界情况？
D3 命名与组织中kebab-case？标准目录结构？文件名自解释？
D4 清晰度与可教性中一个全新的 Claude 实例能无歧义地执行吗？

每个维度用 ✅ / ⚠️ / ❌ 三级评分，每个评审点配套具体改进建议。

  1. 报告模板固定：7 个 section 必须全部输出，确保每次分析的一致性和完整性。从"这是什么"→"怎么用"→"好不好"→"怎么改"——逻辑递进。

九、如何从零开始创建你的第一个技能

Step 1：找到你的"可复制能力"

问自己：我经常重复做的、别人也需要的事情是什么？

举例：

  • 我每次写 PPT 都用同一套 AI workflow → 可以变成技能
  • 我有一个很好用的翻译 prompt 模板 → 可以变成技能
  • 我会用 Claude Code 自动处理 Excel → 可以变成技能
  • 我有一套面试准备流程 → 可以变成技能
Step 2：写 SKILL.md

按标准结构写：

---
name: 你的技能名（kebab-case）
description: >
  一段话描述技能做什么 + 何时触发。列出 3-5 个触发短语。
  越具体越好，越"主动"越好。
---

# 技能标题

## Purpose（为什么需要这个技能）

## Workflow（怎么用，分步骤）

### Step 1 — ...
### Step 2 — ...

## Edge Cases（边界情况）

## Examples（使用示例）
Step 3：测试

自己用一遍。找一个同学用一遍。记录他们遇到的问题。

Step 4：发到群里

按命名规范上传：

YourName_C4_skill说明.md
YourName_C4_技能名.skill（或 .md / .py）
YourName_C4_demo截图.png
YourName_C4_教学说明.md
YourName_C4_AI日志.md

附一句话："这是我的 C4 技能——XXX，输入____就能得到____，欢迎大家试用和反馈！"

Step 5：迭代

根据群友反馈改进，提交 _v2、_v3。每一次迭代都会被记录为"进步"。

Challenge C4A：技能提交自动评审（Automated Skill Submission Evaluator）

🔥 C4 的进阶挑战——不是做一个技能，而是评审所有人的技能。
本质：把 wechat-doc-mapper 的"分类盘点"能力升级为"自动评审"能力。

背景

C4（技能分享与传播）要求每位同学提交一个可复用、可执行、可验证、IO明确的技能包。大家把文件发到 WeChat 群里——但问题来了：

  • 谁交了？谁没交？
  • 交的内容齐不齐？（五个必须文件：skill说明、可执行内容、demo、教学说明、AI日志）
  • 交的内容合不合格？（四条件：可复用、可执行、可验证、IO明确）
  • 能不能自动给出初步评审，而不是等老师一个个看？

现有的 wechat-doc-mapper 技能已经能做第一步（扫描→分类→缺口分析），但它只是"收发室"——能分信，不能阅卷。

C4A 的任务：把收发室升级为自动阅卷系统。

与 C4 的关系

C4C4A
你做什么创建一个技能包，教别人用创建一个评审技能包的技能
输入你的能力 + AIWeChat 群文件夹里所有人的 C4 提交
输出可安装的 .skill 包自动化评审报告（完整性检查 + 质量评分 + 改进建议）
本质能力产品化元能力产品化（评审能力本身变成技能）
与 wechat-doc-mapper 的关系无直接关系以它为起点，升级改造

完成 C4A 的同学同时满足 C4 的要求——因为 C4A 的产出本身就是一个可复用、可执行、可验证的技能。

挑战目标

构建一个 C4 提交自动评审技能，实现以下完整流水线：

WeChat 群文件夹
       ↓
  ① 文件采集与识别
       ↓
  ② 提交完整性检查
       ↓
  ③ 技能质量评审（四条件）
       ↓
  ④ 评审报告生成

挑战结构

阶段时间性质产出
C4A 方案设计发布 → +3天设计阶段方案文档（怎么做、架构图、评审维度定义）
C4A 实现提交+3天 → +7天开发阶段可安装运行的技能包 + 真实评审报告

🏆 首个提交可运行且正确评审至少 3 份真实 C4 提交的同学，直接获得 C4 最高评级。

适用原则

⚡ AI-First 原则： 整个技能的开发过程必须 AI 驱动。你可以用 Claude Code / Cursor / ChatGPT 写代码，用 AI 设计评审维度，用 AI 生成报告模板。每个手动步骤必须反向举证。

📚 拿来主义原则： 必须从 wechat-doc-mapper.skill 出发。不奖励从零开始——奖励"拿来 → 理解 → 改造 → 超越"。说明你拿了什么、改了什么、为什么改。

📛 命名规范： 所有提交文件遵循 姓名拼音_C4A_内容描述.扩展名 格式。

四级任务（由浅入深）

你不需要全部完成。每一级都是独立可提交的成果，越深分越高。

Level 1：文件采集器（Bronze 🥉）
从 WeChat 群文件夹中识别所有 C4 相关提交，按作者分组。

输入：一个本地文件夹路径（WeChat 同步文件夹、手动下载文件夹、或任何包含群文件的目录）
输出：按作者分组的 C4 文件清单

核心能力：

  • 扫描文件夹，识别文件名中的 _C4_ 标记
  • 按命名规范提取作者名
  • 处理不规范命名（回退到文件内容/元数据识别）
  • 支持混合格式（.md, .docx, .pdf, .skill, .py, .mp4, .png）

这一级本质上就是 wechat-doc-mapper 的 C4 聚焦版。 如果你理解了 wechat-doc-mapper 的代码，这一级可以在 30 分钟内完成。

Level 2：完整性检查器（Silver 🥈）
对每个作者的提交，检查 C4 要求的五个必须文件是否齐全。

在 Level 1 基础上，增加：

必须文件检测信号
Skill 说明文档文件名含 skill说明 / skill_doc / skill-doc，或 .md 文件内容含"输入""输出""使用场景"
可执行内容.skill / .py / 含 YAML frontmatter 的 .md / 有代码块的文档
Demo.mp4 / .mov / .png / .jpg / .gif / 含 demo 的文件名
教学说明文件名含 教学 / tutorial / teaching，或内容含"上手""常见坑""步骤"
AI 日志文件名含 AI日志 / AI_log，或内容含"使用的 AI 工具""prompt""迭代次数"

输出：每个作者的完整性报告（✅ 齐全 / ⚠️ 部分缺失 / ❌ 严重缺失）+ 具体缺什么

Level 3：质量评审器（Gold 🥇）
对每个提交的技能内容，按 C4 四条件进行自动评审。

这是核心创新部分。你需要设计如何用 AI（或规则+AI）自动评估以下四个维度：

条件自动评审思路参考
可复用（Reusable）说明文档是否包含环境要求？是否有安装步骤？是否依赖特定本地路径？是否有泛化说明？
可执行（Executable）是否包含可运行代码/prompt/workflow？代码是否有语法错误？.skill 包结构是否完整？
可验证（Verifiable）是否定义了明确的输入输出？是否有测试用例或 demo？是否有预期结果？
IO 明确（Clear I/O）说明文档中是否有"输入____，输出____"的明确描述？类型是否清晰？

每个维度给出：评级（✅ / ⚠️ / ❌）+ 评审依据 + 改进建议

关键设计决策（你需要自己选择）：

方案优点缺点
纯规则（关键词/正则）确定性强，速度快覆盖率低，容易误判
纯 LLM理解力强，灵活不确定，慢，贵
规则 + LLM 混合规则快筛 + LLM 深审架构复杂

你的方案选择本身就是评审的加分项——在方案文档中说明你为什么选这个方案。

Level 4：完整评审系统（Platinum 💎）
生成完整的班级评审报告，含排名、改进建议、趋势追踪。

在 Level 3 基础上，增加：

  • 班级总览仪表板：全班提交状态一览（谁交了、谁没交、总体质量分布）
  • 排名系统：基于四条件评分的综合排名（可配置权重）
  • 改进建议生成：针对每个作者，生成个性化的"下一步行动"
  • 版本追踪：检测 _v2、_v3 等迭代版本，展示进步轨迹
  • 输出格式：Markdown 报告 + Excel 详表 + （可选）HTML 可视化

WeChat 文件获取（开放题）

方案思路

关键约束： 无论你怎么获取文件，你的技能必须接受一个本地文件夹路径作为输入。这样无论文件怎么来的，技能都能工作。

如果你在文件获取这一步有创新方案（比如自动化同步脚本），这是额外加分项。

Challenge C4B：公众号文章生成技能（WeChat Article Pipeline Skill）

🔥 C4 的另一条进阶路线——不是评审技能，而是创造内容发布流水线。
本质：把 Doc-Pipeline 的"格式转换"能力提取出来，变成你自己的公众号文章生成技能。

背景

微信公众号是中国最重要的内容发布平台之一。但从一篇 Markdown 或 Word 文档到一篇排版精美的公众号文章，中间有一系列技术坑：

  • 公众号编辑器只接受 inline CSS——不能用 <style> 标签、不能用 class
  • <h1> 被禁止——要降级为 <h2>
  • <div> 被禁止——要用 <p> 代替
  • <script> 和 <iframe> 被禁止——所有交互性内容失效
  • 图片必须走公众号自己的 CDN——外部链接图片会丢失
  • SVG 在保存时会消失——只有 PNG 能存活

现有的 wechat-html-converter 技能已经能做基础转换，wechat-math-html 能处理数学公式。但它们是通用工具——没有针对"你的内容"做个性化定制。

C4B 的任务：拿到这个 starter kit，用 skill-creator 把它改造成你自己的公众号文章生成技能，并用它发布一篇真实的公众号文章。

与 C4 的关系

C4C4B
你做什么创建任意一个技能包创建一个公众号文章生成技能
起点从零开始或参考示例从 starter kit 出发（拿来主义）
方法论自由发挥必须使用 skill-creator 技能来创建/优化你的技能
验证方式别人用了就行必须发布一篇真实公众号文章
本质能力产品化内容流水线产品化 + 真实发布验证

完成 C4B 的同学满足 C4（技能分享）的最高要求。发布的公众号文章可计入 C7（内容传播）的首篇产出——但 C7 要求持续内容输出和传播数据（阅读量/点赞/转发），单篇文章不自动等同完成 C7。如果你在 C4B 基础上持续发布多篇文章，可同时达成 C7 要求。

挑战目标

Markdown / Word 文档
       ↓
  ① 读取源文件内容
       ↓
  ② 转换为 HTML
       ↓
  ③ 应用公众号排版规则（inline CSS、标签过滤、样式美化）
       ↓
  ④ 输出 copy-paste ready 的 HTML
       ↓
  ⑤ 发布到微信公众号（手动粘贴即可）

你需要做的不只是"让转换跑通"——而是让输出的文章好看、有个性、可定制。

Challenge C4D：本地大模型 Agent 技能（Local LLM Agent Skills with Gemma 4）

🔥 C4 的硬核分支——不依赖云端 API，在你自己的电脑上跑大模型，驱动 Agent 技能。
本质：证明你能在本地设备上运行一个有真实能力的 LLM Agent——不花一分钱 API 费用。

⚠️ 核心挑战：在你自己的设备上运行 Agent

Google 刚刚发布了 Gemma 4——四款开源模型，Apache 2.0 协议，专为本地运行和 Agent 工作流设计。

你的任务：

  1. 在你的电脑/手机上下载并运行 Gemma 4 模型
  2. 用本地模型驱动 Agent 技能——执行函数调用、生成结构化输出、完成多步任务
  3. 生成一个交互式地图——展示 SIAS University（郑州西亚斯学院）或其他有意义的地点
  4. 截图/录屏发群里证明是在本地跑的
💡 为什么要本地跑？因为数据主权和零成本推理是 AI 工程师的核心能力。云端 API 会断、会涨价、会审查——但你本地的模型永远属于你。

📊 Gemma 4 家族：四款模型，你跑哪个？

最简示例（Python + Ollama + Folium）
import requests, json, folium

# 1. 用本地 Gemma 4 生成地点数据
response = requests.post("http://localhost:11434/v1/chat/completions", json={
    "model": "gemma4",
    "messages": [
        {"role": "system", "content": "You are a geography assistant. Always respond with valid JSON only."},
        {"role": "user", "content": """List 8 notable locations at or near SIAS University (西亚斯学院) 
         in Xinzheng, Henan, China. Return JSON array with fields: 
         name, name_zh, latitude, longitude, description"""}
    ]
})

# 2. 解析模型输出
data = json.loads(response.json()["choices"][0]["message"]["content"])

# 3. 生成交互式地图
m = folium.Map(location=[34.40, 113.73], zoom_start=14)
for loc in data:
    folium.Marker(
        [loc["latitude"], loc["longitude"]],
        popup=f"<b>{loc['name_zh']}</b><br>{loc['description']}",
        tooltip=loc["name"]
    ).add_to(m)
m.save("sias_map.html")
print("地图已生成：sias_map.html")
