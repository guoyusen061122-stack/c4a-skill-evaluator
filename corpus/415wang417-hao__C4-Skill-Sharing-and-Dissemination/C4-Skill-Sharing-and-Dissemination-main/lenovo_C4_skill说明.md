# smart-file-organizer 技能说明

> 技能包文件：`lenovo_C4_smart-file-organizer.skill`
> 技能名：`smart-file-organizer`（文件夹智能归类助手）
> 类别：文件管理 / 桌面整理

---

## 一、技能解决什么问题

桌面和下载文件夹会持续堆积散落文件：截图、合同、视频、安装包、代码混在同一层，想找一份具体文件只能靠肉眼逐个扫。手工拖拽分类存在三个固有问题：**慢**（一个中等规模的乱目录需要十几分钟）、**易漏**（同类文件常被落下几个）、**不可逆**（拖到一半发现分错类，很难改回去，误拖还可能覆盖同名文件）。

smart-file-organizer 把这件事压缩成一条命令，并针对上述三个问题分别给出对策：

| 手工整理的痛点 | 技能的对应设计 |
|---|---|
| 慢，逐个拖拽 | 一条命令批量归类，三秒内完成几十个文件 |
| 易漏，靠肉眼识别 | 按扩展名映射表穷举分类，未命中归入「其他」而非被忽略 |
| 不可逆，分错难改 | 每次执行生成 undo 清单，`--undo` 一键还原到整理前 |
| 可能覆盖同名文件 | 目标重名时自动追加 `_1`、`_2` 后缀，绝不覆盖 |
| 误伤隐藏/系统文件 | 自动跳过 `.` 开头文件、`desktop.ini`、`thumbs.db` 及带隐藏/系统属性的文件 |

技能采用**只移不删**原则：全程不做任何删除动作，最坏情况也只是文件位置变化，且可通过 undo 清单还原。运行仅依赖 Python 标准库，无需安装任何第三方包。

---

## 二、适用场景

**推荐使用**

- 桌面、下载文件夹长期未整理，顶层堆积大量散落文件
- 按时间归档照片、截图、录屏（用 `date` 策略生成 `2026-09/` 这样的年月文件夹）
- 从一堆杂文件中挑出特定主题的文件，如把合同、发票、简历单独归拢（用 `keyword` 策略）
- 整理前需要先看方案、确认无误再动手（`--dry-run` 预览）
- 整理后效果不满意，需要一键退回（`--undo`）

**不适用**

| 场景 | 原因 | 建议 |
|---|---|---|
| 需要递归整理子文件夹内部 | 工具只处理顶层散落文件，刻意不递归以免打乱既有结构 | 对目标子目录单独执行一次 |
| 需要删除重复文件 | 工具只移不删，不做去重 | 使用专门的文件去重工具 |
| 需要调整桌面图标位置、排序 | 属于操作系统桌面管理能力，与文件归类无关 | 使用系统自带或专门的桌面管理工具 |
| 需要格式化磁盘、调整分区 | 属于磁盘管理范畴 | 使用磁盘管理工具 |

## 三、输入输出（一句话说清）

**输入** = 一个目标目录 + 一个归类策略（`type` 按类型 / `date` 按修改年月 / `keyword` 按关键词）；
**输出** = 归类后的目录结构 + 一份 Markdown 归类报告 + 一份可回滚的 undo 清单 JSON。

| 项目 | 内容 |
|---|---|
| 输入 1 | 目标目录绝对路径（必填） |
| 输入 2 | `--strategy type \| date \| keyword`（默认 `type`） |
| 输入 3 | `keyword` 策略所需的 `--keywords 发票,合同,简历`（逗号分隔） |
| 输入 4 | 可选开关：`--dry-run`（预览）/ `--undo`（还原）/ `--undo-file <路径>`（指定清单） |
| 输出 1 | 归类后的目录结构（文件移入以类别命名的子文件夹） |
| 输出 2 | `_organize_report_<时间戳>.md` —— 归类概览、文件明细、跳过清单、结果统计 |
| 输出 3 | `_organize_undo_<时间戳>.json` —— 每条移动的 src/dst 记录，供还原使用 |

## 四、安装与使用步骤

### 4.1 环境要求

- Python 3.7 或更高版本
- 仅使用标准库（`os`、`pathlib`、`json`、`argparse`、`datetime`、`ctypes`），**无需 pip 安装任何包**
- 对目标目录具备读写权限

### 4.2 安装

`.skill` 文件本质是 ZIP 压缩包。将其解压到技能目录即可：

```bash
python -c "import zipfile; zipfile.ZipFile('lenovo_C4_smart-file-organizer.skill').extractall('<技能安装目录>')"
```

解压后目录结构：

```
smart-file-organizer/
├── SKILL.md                              # 技能主文件（YAML frontmatter + 使用说明）
├── scripts/
│   └── organize.py                       # 核心脚本（18,360 字节，纯标准库）
└── references/
    ├── organizing-strategies.md          # 扩展名映射表与策略细节
    └── pitfalls.md                       # 14 条常见坑与排查方法
```

### 4.3 使用四步法

```bash
# 第一步：预览（务必先做，不移动任何文件）
python scripts/organize.py "<目标目录>" --strategy type --dry-run

# 第二步：确认无误后实际归类
python scripts/organize.py "<目标目录>" --strategy type

# 第三步：查看生成的 _organize_report_<时间戳>.md

# 第四步：不满意则一键还原
python scripts/organize.py "<目标目录>" --undo
```

## 五、策略说明

| 策略 | 归类依据 | 生成文件夹示例 | 典型用途 |
|---|---|---|---|
| `type` | 文件扩展名 → 9 大类 | `图片/`、`文档/`、`视频/`、`音频/`、`压缩包/`、`代码/`、`程序/`、`字体/`、`其他/` | 通用整理，最常用 |
| `date` | 文件修改时间 → `YYYY-MM` | `2025-08/`、`2026-03/`、`2026-09/` | 照片、截图、录屏按时间归档 |
| `keyword` | 文件名包含关键词 | `发票/`、`合同/`、`简历/`、`其他/` | 从杂文件中抽取特定主题 |

`type` 策略的扩展名映射覆盖 9 大类共约 130 种扩展名，完整清单见 `references/organizing-strategies.md`。未命中任何映射的扩展名（含无扩展名文件）统一归入 `其他/`。

`keyword` 策略的匹配不区分大小写，按 `--keywords` 传入顺序确定优先级：文件名同时包含「发票」和「合同」时，取列表中靠前的关键词。

## 七、技术实现与安全设计

| 设计点 | 实现方式 |
|---|---|
| 预览模式 | `--dry-run` 只计算目标路径并打印，不调用任何移动操作 |
| 只移不删 | 代码中不包含任何删除文件的调用，空目录清理仅针对本次新建的目录 |
| 冲突保护 | `unique_path()` 检测目标是否存在，存在则追加 `_1`、`_2` 直至不冲突 |
| 隐藏文件识别 | 双重判断：文件名以 `.` 开头或在跳过名单中，或具有 Windows 隐藏/系统属性（通过 `ctypes` 读取文件属性） |
| 工具产物保护 | 以 `_organize_` 开头的文件自动跳过，避免报告和清单被再次归类 |
| 失败隔离 | 单个文件移动失败被记录为 `failed` 并写入报告，不中断整体流程 |
| 可追溯 | 报告与 undo 清单均含时间戳，多次执行互不覆盖 |
| 零依赖 | 仅使用 Python 标准库，跨平台可用（Windows 隐藏/系统属性检测为可选增强，非 Windows 环境自动降级） |

## 八、已知限制

1. **不递归**：只整理目标目录顶层的散落文件，已有子文件夹保持不动。这是刻意设计，避免打乱用户既有的分类结构；如需整理子目录内部，请对其单独执行。
2. **跨盘移动较慢**：同盘移动是改名操作（毫秒级），跨盘（如 C: → D:）会退化为复制加删除，大文件量下耗时明显。
3. **`date` 策略依据修改时间**：若文件的修改时间被复制、下载等操作改写，归档结果会以改写后的时间为准。
4. **`keyword` 策略依赖命名**：仅匹配文件名，不读取文件内容，因此命名不规范的文件无法被关键词命中，会落入 `其他/`。
