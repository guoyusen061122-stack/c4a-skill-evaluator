# deliverable-checker 作业交付物自查器 — Skill 说明

> C4 提交 ｜ 作者：苗文馨 ｜ 挑战：ch-20260717031424-4cdgor ｜ 技能版本 v1.2

## 一句话说明

**输入**挑战资料包目录 + 你的提交文件夹，**输出**一份自查报告：缺了什么交付物、命名是否合规、会踩哪些红旗、五维评分证据是否齐全。

## 解决什么问题

每次交作业（C1–C7）前，每个人都会焦虑同样的三个问题：

1. **我交齐了吗？** —— 官方要求 5 项交付物，我数了三遍还是不放心
2. **命名对吗？** —— `姓名_C编号_说明.ext`，一个下划线写错可能就找不到
3. **会踩红旗吗？** —— 忘了写 AI 日志，5 分就没了，而我自己根本没意识到

这些检查本质上是**机械核对**：拿官方 challenge.json 里的 `required_deliverables`
通配符，去匹配你文件夹里的文件名。机械核对就该交给脚本——这正是本技能的设计原点。

## 技能四条件自证

| 条件 | 自证 |
|------|------|
| 可复用 | 纯 Python 标准库，零第三方依赖，Windows/macOS/Linux 任何机器可跑；不绑定我的环境 |
| 可执行 | 确定性 Python 脚本（`scripts/deliverable_checker.py`），带完整 CLI |
| 可验证 | 同样输入永远同样输出；有缺失时退出码 1，输入错误退出码 2，全通过退出码 0（可接 CI） |
| IO 明确 | 输入 = 2 个文件夹路径（+可选姓名）；输出 = Markdown 自查报告 + 可选 JSON |

## 使用场景

- 每次挑战提交前，跑一遍自查（C1–C7 通用，只换资料包路径）
- 群里收作业的助教/组织者：批量扫描所有人的文件夹，输出缺口清单
- 提交后把自查报告一起上传，向助教证明"提交前已自查"

## 输入输出

```
输入：
  --challenge   挑战资料包目录（含 challenge.json）
  --submission  你的提交文件夹（递归扫描）
  --name        你的姓名（用于命名建议，可选）
  --pattern     （没有 challenge.json 时）直接给通配符清单，如 "*skill说明*,*.skill"
输出：
  Markdown 自查报告（5 节：交付物核对 / 命名检查 / 红旗预警 / 五维自查 / 行动清单）
  + 可选 --json 机器可读结果
```

## 使用步骤（60 秒上手）

```bash
# 1. 下载技能包并解压（或安装到你的 AI 环境）
# 2. 运行：
python deliverable_checker.py --challenge "E:/挑战合集/挑战_C4_完整资料" --submission "E:/我的提交/C4" --name "苗文馨"
# 3. 看报告第 5 节「行动清单」，逐条修复
# 4. 修完再跑一遍，退出码 0 = 可以提交
```

装进 AI 环境（如 WorkBuddy / Claude）后，直接说："**帮我自查一下 C4 的提交文件夹**"，AI 会自动调用本技能。

## 真实案例（本技能开发过程中的实测）

**案例 1 — 缺漏提交检出**：构造了一个只含 2 个文件的模拟提交。
脚本正确报告 4 项交付物缺失、1 个文件命名不合规（`笔记.md`）、2 个红旗触发（missing_artifacts + no_ai_log）、退出码 1。

**案例 2 — 边界情况**：空文件夹（报"0 个文件"不崩溃）、无 challenge.json 时 `--pattern` 兜底、
错误目录退出码 2 并给出修复提示、JSON 输出可解析——5 项边界测试全部通过。

**案例 3 — 官方资料包实测**：对本挑战（C4）资料包实测，`required_deliverables` 的 5 个模式
全部正确解析并核对。

## 设计决策（为什么值得用）

1. **脚本驱动而非指令驱动**：核对交付物需要 100% 确定性，"感觉交齐了"不够——脚本每次给出完全一致的判定。
2. **诚实边界**：脚本只回答"有没有、叫什么"，明确标注"内容质量请人工/AI 复核"，不假装能评 25 分的技能质量。
3. **YAML/JSON 数据驱动**：换一个挑战只需换资料包，无需改代码；没有 challenge.json 也能用 `--pattern` 裸跑。
4. **行动导向输出**：报告终点永远是按优先级排序的行动清单，每条缺失对应一条具体修复动作。

## 已知限制

- `one_shot_ai` 红旗（一句话指令提交、无迭代）无法从文件系统判定，报告中不判定此红旗
- 只核对文件名与存在性，不读文件内容（内容质量需 AI/人工）
- rubric 维度证据映射是启发式的（如 `*demo*` 算可教性证据），极端命名可能漏判
