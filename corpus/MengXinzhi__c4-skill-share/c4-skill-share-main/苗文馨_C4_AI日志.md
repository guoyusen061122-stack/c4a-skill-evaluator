## Round 1 — 选题与骨架

**我的 prompt（第 1 轮）：**
> "帮我完成这个挑战"（附上 challenge.json / CHALLENGE.md / rubric.json / 两个示例 .skill）

**AI 做了什么：**
- 通读全部资料，提炼评分权重：最高权重是「被使用次数」→ 技能必须选**人人都用得上**的事，而非炫技
- 给出选题推理：Elite20 每次交作业人人都需要"提交前自查"，高频、零门槛、可验证 → 定名 **deliverable-checker**
- 按 CHALLENGE.md 第七节的标准结构搭出技能包：

```
deliverable-checker/
├── SKILL.md                      # frontmatter + 工作流 + 边界情况（约 180 行）
├── scripts/deliverable_checker.py # 确定性核对脚本（约 300 行）
└── references/rubric-guide.md     # 评分维度证据映射说明
```

**我的决策点：** AI 提出两个备选（自查器 / AAR 生成器）。我选了自查器——AAR 写作有判断成分、
难以"可验证"，自查器是纯机械核对，更符合四条件里的「可执行 + 可验证」。

## Round 2 — 第一轮实测（发现真 bug）

**我的 prompt（第 2 轮）：**
> "先造一个故意缺漏的模拟提交文件夹，实际跑一遍，不要只看代码就下结论"

**实测结果（对官方 C4 资料包）：**
核心功能全部正确：5 项交付物模式解析正确、4 项缺失被检出、命名违规（`笔记.md`）被标记、
2 个红旗触发、退出码 1。

**⚠️ 发现的真问题：** `苗文馨_C4_skill说明.md` 被算作「技能质量」维度的证据——
原因是我当初的映射规则 `*SKILL*` 会误伤"skill**说明**文档"。说明文档不是可执行技能，
这个误判会让自查报告给出虚假的安全感。

**修复：** skillQuality 的证据模式收紧为 `*.skill / *.py / *SKILL.md* / *workflow* / *prompt*`，
复测后 `skill说明.md` 不再误判。教训写进了 rubric-guide.md："通配符要按语义边界设计，不按子串"。

## Round 4 — 打包、Demo 与文档（坑最多的一轮）

**这一轮连踩三个真实的坑，全部如实记录：**

**坑 1：.skill 格式的"官方说法 vs 实物不符"。**
CHALLENGE.md 说 .skill 是 tar.gz，但解包随附的两个示例时 Python 报
`BadGzipFile: Not a gzipped file (b'PK')`——**PK 魔数说明实际是 ZIP**。
处置：我的 .skill 包按实测事实用 ZIP 打包（兼容性反而更好），并把此发现写进教学说明。

**坑 2：执行环境缺 coreutils。**
会话的 bash 环境连 `ls / grep / mkdir` 都找不到（PATH 损坏），PowerShell 输出捕获也异常。
处置：改用 Python 全路径 + `subprocess` 跑测试，反而让测试矩阵变成了可复跑的脚本
（edge_tests.py 思路）——因祸得福。

**坑 3：pip 安装 Pillow 被网络策略拦截（SIGTERM×3）。**
Demo 截图本来计划用 PIL 渲染。处置：**不换目标，换路径**——改用 Windows 自带的
GDI+（System.Drawing）渲染终端风格截图，零第三方依赖。这也呼应了技能本身的设计哲学。

## AAR 复盘

**做得好的：**
1. 每轮都"实测而非目测"——R2 的映射误判靠真实运行才暴露，代码审查看不出来
2. 坑没有绕过去，而是变成产出：ZIP 发现写进教学说明、测试脚本成为 AI 日志证据

**失败/受限的：**
1. 第一版评分映射想当然（`*SKILL*`），说明"通配符即接口"——接口设计要按语义边界
2. 环境问题耗时比例偏高（PATH 损坏、pip 被拦），下一个技能应先做环境探测清单再动手
3. `one_shot_ai` 红旗无法由脚本判定——工具的诚实边界，但也提示 v2 可以加"文件 mtime 聚类"启发式

**改进方案（v2 路线）：**
- 增加 `--batch` 模式：扫描全班文件夹一次输出汇总矩阵（助教视角，扩大使用人群）
- 增加 GitHub Action 示例：push 前自动自查，退出码拦截
- 把 rubric 证据映射外置为 YAML（向 wechat-doc-mapper 的注册表设计看齐）
