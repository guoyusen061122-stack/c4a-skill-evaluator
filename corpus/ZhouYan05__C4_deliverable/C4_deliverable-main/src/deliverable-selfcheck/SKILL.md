# deliverable-selfcheck · 挑战交付物自检器

## 这个技能解决什么问题

EduSeed 平台在提交挑战时会做交付物校验，但它的校验有两个不直观的地方，
导致学生"文件明明写了"却被判缺失、或者整单被拒之门外：

1. **通配符是文件名的字面子串匹配，不是模糊匹配。**
   要求 `*AI日志*` 时，文件 `AI_工作日志与AAR.md` **不匹配**——下划线把
   「AI」和「日志」断开，文件名里并不字面存在 `AI日志` 这四个连续字符。
   同一文件却能被 `*AAR*` 匹配。
2. **标题/摘要里的「英文冒号 + 空格」会被敏感信息过滤误判成密钥形态。**
   `C4 技能： 交付物自检` 这类写法可能整单被拒：
   `字段「projectTitle」提交内容疑似包含敏感信息（密钥/Token）。请脱敏后重新提交。`

本技能把这两条坑（外加空文件、命名前缀、必备文件等常规检查）
固化成**一条可复跑的命令**，在提交前给出确定性的判定。

## 输入 / 输出契约

输入（全部通过命令行参数给出，无需交互）：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--workdir` | 是 | 你的交付物所在目录（绝对路径或相对当前目录） |
| `--required` | 是 | 挑战要求的交付物，逗号分隔的通配符，如 `"*AI日志*,*AAR*,*.py"` |
| `--prefix` | 否 | 你的命名前缀（如 GitHub 用户名 `ZhouYan05`），用于检查文件名是否带前缀 |
| `--title` | 否 | 你准备提交的标题，检查敏感信息误判形态 |
| `--summary` | 否 | 你准备提交的摘要，同上 |
| `--json` | 否 | 输出机器可读 JSON（默认输出 Markdown 报告） |

输出：一份 Markdown 报告（或 `--json` 时的 JSON），包含

- `missing`：**按平台字面语义**判定为缺失的交付物（附「模糊匹配本可命中」的提示）
- `found`：每项交付物命中的文件（平台语义 / 模糊语义 双列）
- `warnings`：空文件、无前缀、命名歧义、敏感词形态等
- `verdict`：`READY` / `BLOCKED`，以及阻断原因

## 使用方法

```bash
python scripts/selfcheck.py \
  --workdir ./my_challenge \
  --required "*AI日志*,*AAR*,*.py" \
  --prefix ZhouYan05 \
  --title "C4 技能分享 - deliverable-selfcheck" \
  --summary "一个把平台提交坑固化成检查的交付物自检器"
```

退出码：`0` = READY，`1` = BLOCKED（可直接用于 CI 或脚本串联）。

## 工作流程（给使用本技能的 AI）

1. 先向用户确认三件事：工作目录、挑战要求的交付物清单（可让用户从挑战页复制）、
   命名前缀。三者都能从上下文推断时不要追问。
2. 运行 `scripts/selfcheck.py`，把 `verdict=BLOCKED` 的每一项翻译成
   「用户能直接做的一步」，不要只说"缺少 X"。
3. 若报告出现 `LITERAL_MISMATCH`：**不要建议改平台**，建议**改文件名**，
   并给出一个同时能命中多个关键词的新名字（例如把
   `AI_工作日志与AAR.md` 改成 `AI日志与AAR.md`，一次命中两类交付物）。
4. 若报告出现 `SENSITIVE_SHAPE`：把冒号换成破折号或全角冒号，其余内容不动。
5. 修完后**再跑一次**，以第二次的 `verdict` 为准。

## 边界（不要做的事）

- 本技能**不代替平台检查**。它是平台的近似实现，用于提前发现问题；
  最终以 `prepare-submission` / `submit` 的返回为准。
- 本技能**不提交、不上传、不修改你的文件**，只读。
- 缺交付物时**不要**为了过关创建空文件或占位文件——那会触发
  `missing_artifacts` 红标，影响完成度评分。宁可少而实。

## 已知局限

- 字面语义是按平台实测行为近似实现的，平台后续版本可能变更。
- 敏感词形态检查覆盖「英文冒号+空格」和常见密钥前缀（`sk-`、`ghp_` 等），
  不是全量敏感词库。
- 不解析 PDF/Word 正文，只做文件名与文本字段层面的检查。
