## 1. 一句话说明

**在提交课程挑战之前，用一条命令告诉我：交付物缺不缺、文件名对不对、会不会被平台的敏感信息过滤拦下。**

## 2. 它为什么存在（来自真实踩坑）

EduSeed 平台的提交校验有两个不直观的地方，我在完成 C1–C3 时真的被卡过：

**坑一：通配符是文件名的「字面子串匹配」，不是模糊匹配。**

挑战要求 `*AI日志*`，我交的文件叫 `AI_工作日志与AAR.md`。
直觉上应该命中，但平台判**缺失**——因为下划线把「AI」和「日志」断开，
文件名里并不存在 `AI日志` 这个**连续**字符串。同一个文件却能匹配 `*AAR*`。
结果就是：我明明写了日志，却拿到 `missing_artifacts`，完成度分被压到 ≤5/15。

**坑二：标题里的「英文冒号 + 空格」会被误判成密钥。**

标题写成 `C4 技能分享: deliverable-selfcheck` 会被整单拒绝：

```
字段「projectTitle」提交内容疑似包含敏感信息（密钥/Token（sk- 或 api key 形态））。请脱敏后重新提交。
```

这不是真密钥，只是 `词: 词` 的观感触发了过滤。改成破折号或全角冒号即可通过。

这两条坑是**可检测的**——所以我把它做成了工具，而不是写进备忘录。

## 3. 它做什么

输入一个目录 + 挑战要求的交付物清单，输出：

| 输出项 | 含义 |
| --- | --- |
| `missing` / `found` | 按**平台字面语义**逐项判定，并按**直觉通配符语义**给出对照 |
| `LITERAL_MISMATCH` | 「直觉上能命中、平台却判缺失」的文件，附改名建议 |
| `EMPTY_FILE` | 0 字节的占位文件（会拉低完成度） |
| `MISSING_PREFIX` | 顶层交付物文件名缺少命名前缀 |
| `SENSITIVE_SHAPE` | 标题/摘要里的「英文冒号+空格」风险片段 |
| `SENSITIVE_KEY` | 命中 `sk-` / `ghp_` / `api key=` 等真实密钥形态，提示立即吊销 |
| `verdict` | `READY` / `BLOCKED`；退出码 0 / 1，可直接串进脚本 |

## 4. 四个条件的自评（C4 要求：可复用 / 可执行 / 可验证 / IO 明确）

- **可复用**：与具体挑战无关。任何挑战、任何学期，只要把挑战页的交付物清单
  复制进 `--required` 就能用。21 个挑战通用。
- **可执行**：`scripts/selfcheck.py`，纯 Python 标准库，**零依赖**。
  在任意装了 Python 3 的机器上可直接跑，不需要装包、不需要联网。
- **可验证**：判定是确定性的——同样的目录和参数，输出永远相同；
  退出码可被 CI 或脚本直接消费。仓库里的 `_demo/before` 与 `_demo/after`
  是两个可复跑的对照样本。
- **IO 明确**：输入 = 目录 + 通配符清单 + 前缀/标题/摘要（全部命令行参数，
  无需交互）；输出 = Markdown 报告或 `--json` 的 JSON。

## 5. 结构

```
deliverable-selfcheck/
├── SKILL.md                     # 技能入口：何时用、怎么用、边界
├── scripts/selfcheck.py         # 全部逻辑，纯标准库
├── references/rulebook.md       # 平台规则速查（每条坑的实测证据）
└── assets/report_template.md    # 报告模板与 JSON 形态
```

采用三层加载：元数据（约 100 词，常驻）→ SKILL.md 正文（触发时读）
→ 附件（按需读）。所以它不会一直占用上下文。

## 6. 用法

```bash
python scripts/selfcheck.py \
  --workdir ./my_challenge \
  --required "*skill说明*,*.skill,*教学说明*,*demo*,*AI日志*" \
  --prefix ZhouYan05 \
  --title "C4 技能分享 - deliverable-selfcheck" \
  --summary "把平台提交坑固化成可执行检查的小工具"
```

## 7. 边界与局限（诚实说明）

- **不替代平台校验**，是它的近似实现，用来提前发现问题；最终以平台返回为准。
- **只读**：不提交、不上传、不修改文件。
- **不解析 PDF/Word 正文**，只做文件名与文本字段层面检查。
- 敏感词库是实测中冒出来的几个形态，不是全量词库。
- **不支持「用空文件蒙混过关」**——报告会明确把占位文件标成风险，
  因为缺交付物的正确做法是补内容，不是凑数。
