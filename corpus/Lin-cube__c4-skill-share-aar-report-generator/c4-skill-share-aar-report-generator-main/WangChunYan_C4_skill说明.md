# WangChunYan_C4_skill说明.md

> 技能名：**aar-report-generator（AAR 复盘报告生成器）**
> 一句话：**输入**一次经历/项目的结构化复盘记录，**输出**一份分章节、可行动的 Markdown 复盘报告 + 复盘深度自检。

---

## 一、解决什么问题

复盘（After Action Review）是「从经历里提炼可复用经验」的关键动作。但大多数人复盘只有一句感想：

- ❌ 只有结果没有目标 → 不知道「到底算好还是不好」
- ❌ 只有流水账没有归因 → 下次依然犯同样的错
- ❌ 归因指向外部（「运气不好」「队友不给力」）→ 无法指导自己改变
- ❌ 有感悟没有行动 → 复盘完就忘了，等于白复盘

这个技能把复盘变成**结构化、可验证**的过程，强制覆盖完整闭环：

```
目标 → 过程 → 结果 → 根因 → 教训 → 行动
```

并自动输出「复盘深度自检」，让你客观看到这次复盘覆盖了几个维度、还缺什么。

---

## 二、使用场景

| 场景 | 举例 |
|------|------|
| 项目/任务结束复盘 | 做完一次公开分享、一次考试、一个 sprint 后总结 |
| 学习复盘 | 一次比赛、一次面试、一门课程结束后的反思 |
| 产品/内容迭代 | 发布 v1 后，根据反馈总结并规划 v2 |
| 团队协作复盘 | 一次活动、一次合作结束后对齐经验 |
| 个人习惯养成 | 每周/每月回顾，沉淀「保持/改进/开始/停止」 |

## 三、输入与输出（IO 明确）

### 输入（二选一）

1. **JSON 文件**（字段完整、支持量化指标）：

```json
{
  "title": "第一次公开演讲",
  "objective": "讲清楚一个概念，让听众记住一个要点",
  "what_happened": "准备了一周，写了逐字稿……",
  "result": "反响不错，但 3 人反馈语速太快",
  "keep": ["写了逐字稿，控制了结构"],
  "improve": ["语速太快，重点没停顿"],
  "root_causes": ["紧张导致赶进度"],
  "lessons": ["提前标注停顿点"],
  "action_items": [{"action": "加停顿标记", "owner": "我", "deadline": "2026-02-10", "priority": "高"}]
}
```

2. **「标签: 值」纯文本**（非程序员也能写，列表用 `-` 开头）：

```text
标题: 第一次公开演讲
目标: 讲清楚一个概念
过程: 准备了一周……
结果: 反响不错，但语速太快
做对了:
- 写了逐字稿
根因:
- 紧张导致赶进度
行动计划:
- 加停顿标记 | 我 | 2026-02-10 | 高
```

### 输出

一份完整 Markdown 报告，固定包含 9 大章节：

1. 背景与目标（预期是什么）
2. 实际过程（实际发生了什么）
3. 结果与差距
4. 复盘四问（预期 / 实际 / 为什么有差距 / 下次怎么做）
5. 保持 · 改进 · 开始 · 停止（四象限）
6. 根因分析（5 Why）
7. 经验教训（可复制的洞察）
8. 行动计划（SMART）
9. 一句话总结 + **复盘深度自检（6 维度打分）**

## 四、使用步骤

### 方式 A：脚本路径（确定性，推荐给需要固定格式的人）

```bash
# 1. 生成空白模板（JSON）
python aar_report.py --template -o 我的复盘.json

# 2. 填好模板后，生成报告
python aar_report.py 我的复盘.json -o 我的复盘.md

# 3. 或用纯文本输入
python aar_report.py 我的复盘.txt -o 我的复盘.md
```

### 方式 B：指令路径（灵活性，推荐给不想碰代码的人）

把技能装到 Claude 后，直接说：

> 「帮我复盘一下这次考试没考好」

技能会按框架用「复盘四问」引导你补全信息，再生成报告，无需任何脚本。

### 方式 C：快速看效果

```bash
python aar_report.py --sample   # 用内置示例跑一次
```

| 深度自检 | 6 / 6 分（完整闭环） |
