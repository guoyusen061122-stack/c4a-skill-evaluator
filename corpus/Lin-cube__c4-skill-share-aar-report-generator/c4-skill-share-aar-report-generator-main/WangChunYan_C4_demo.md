## 0. 环境

- 系统：Windows
- Python：3.13.2（技能要求 3.8+，仅用标准库）

---

## 1. 第一步：生成空白模板

命令：

```bash
python aar_report.py --template -o 模板.json
```

输出文件 `模板.json`（节选）：

```json
{
  "title": "在这里填写复盘主题",
  "objective": "预期目标是什么？你希望在这次经历里达成什么？",
  "what_happened": "实际发生了什么？按时间顺序或关键节点描述过程。",
  "result": "最终结果如何？与预期相比差在哪、好在哪？",
  "action_items": [
    {"action": "具体可执行的下一步", "owner": "我", "deadline": "YYYY-MM-DD", "priority": "高"}
  ]
}
```

---

## 2. 第二步：用内置示例跑一次（JSON 输入）

命令：

```bash
python aar_report.py --sample
```

真实输出（完整）：

```markdown
# AAR 复盘报告：第一次在群里分享自研技能

> 复盘日期：2026-01-15 ｜ 生成工具：aar-report-generator v1.0.0

## 一、背景与目标（预期是什么）
把我的「复盘报告生成器」技能教会 10 个同学，并让至少 5 个人真正用起来。

## 二、实际过程（实际发生了什么）
我先在群里发了一条技能介绍和安装说明，附上了一个示例。当天有 3 个同学回复说装好了，
但第二天只有 1 个人反馈真正跑通了。我私聊了那些说「看不懂」的同学，发现大家卡在
「JSON 输入不会写」这一步。于是我补了一个纯文本模板和一张截图，重新发了一遍。

## 三、结果与差距
最终有 6 个同学成功跑通并输出了自己的复盘报告，达成了「5 人使用」的目标，但没有达到「10 人学会」。

| 指标 | 数值 |
|------|------|
| 回复人数 | 11 |
| 成功使用人数 | 6 |
| 目标使用人数 | 5（超额 1 人） |

## 四、复盘四问

| 问题 | 回答 |
|------|------|
| 1. 预期是什么？ | 把我的「复盘报告生成器」技能教会 10 个同学，并让至少 5 个人真正用起来。 |
| 2. 实际发生了什么？ | 我先在群里发了一条技能介绍和安装说明，附上了一个示例。当天有 3 个同学回复说装好了… |
| 3. 为什么有差距？ | 高估了大家对 JSON 的熟悉程度…；没有做「冷启动测试」… |
| 4. 下次怎么做？ | 把说明改成「纯文本模板 + 截图」双入口；找 1 个非技术同学做冷启动测试… |

## 五、保持 · 改进 · 开始 · 停止

| 保持 Keep | 改进 Improve |
|-----------|-------------|
| 附上一个可直接跑的示例，极大降低了上手门槛 | 第一版说明太依赖 JSON，没照顾非技术同学 |
| 对「看不懂」的人主动私聊跟进 | 发布前没有找人试读一遍说明 |

| 开始 Start | 停止 Stop |
|------------|-----------|
| 发布前先找 1 个同学试跑一次 | 一次性发大段文字，导致大家没有耐心读完 |
| 为每个常见报错写一句「怎么办」 | — |

## 六、根因分析（5 Why 追问）

- 高估了大家对 JSON 的熟悉程度（为什么？因为我是用代码的习惯去写说明）
- 没有做「冷启动测试」——让一个完全陌生的人按说明操作（为什么？因为我默认大家和自己一样）

## 七、经验教训（可复制的洞察）

- 截图和「先跑通再优化」比大段文字更有效
- 发布前做一次「陌生人测试」，能提前发现 80% 的卡点
- 「被使用」比「写得漂亮」更重要，简单可用 > 复杂完整

## 八、行动计划（SMART）

| 优先级 | 行动 | 负责人 | 截止时间 |
|--------|------|--------|----------|
| 高 | 把说明改成「纯文本模板 + 截图」双入口 | 我 | 2026-01-18 |
| 高 | 找 1 个非技术同学做冷启动测试并记录卡点 | 我 | 2026-01-20 |
| 中 | 发布 v2 并收集反馈 | 我 | 2026-01-22 |

## 九、一句话总结

「第一次在群里分享自研技能」的复盘结论是，关键教训：截图和「先跑通再优化」比大段文字更有效；
发布前做一次「陌生人测试」，能提前发现 80% 的卡点，下一步：把说明改成「纯文本模板 + 截图」双入口；
找 1 个非技术同学做冷启动测试并记录卡点。

## 复盘深度自检（自动生成）

| 维度 | 评级 | 说明 |
|------|------|------|
| 目标明确 | ✅ | 是否写清了「预期是什么」 |
| 过程记录 | ✅ | 是否记录了「实际发生了什么」 |
| 结果量化 | ✅ | 是否有结果描述（有量化指标更佳） |
| 根因分析 | ✅ | 是否追问了「为什么有差距」 |
| 经验提炼 | ✅ | 是否沉淀了可复制的教训 |
| 行动落地 | ✅ | 是否有带负责人/截止时间的行动项 |

**深度得分：6 / 6**

✅ 这次复盘覆盖了完整闭环（目标→过程→结果→根因→教训→行动），可以直接用于下次行动。
```

## 3. 第三步：纯文本输入（照顾非程序员）

输入文件 `examples/sample_text_input.txt`：

```text
标题: 第一次公开演讲
日期: 2026-02-01
目标: 讲清楚一个概念，让听众记住一个要点
过程: 准备了一周，写了逐字稿，现场讲了 20 分钟
结果: 现场反响不错，但有 3 个人反馈语速太快
做对了:
- 写了逐字稿，控制了结构
- 提前到场试了设备
需改进:
- 语速太快，重点没停顿
根因:
- 紧张导致赶进度
经验教训:
- 提前标注停顿点，把「慢下来」写进逐字稿
行动计划:
- 在逐字稿里加停顿标记 | 我 | 2026-02-10 | 高
```

命令：

```bash
python aar_report.py examples/sample_text_input.txt -o examples/sample_text_output.md
```

关键输出（第八、九章 + 自检）：

```markdown
## 八、行动计划（SMART）

| 优先级 | 行动 | 负责人 | 截止时间 |
|--------|------|--------|----------|
| 高 | 在逐字稿里加停顿标记 | 我 | 2026-02-10 |

## 九、一句话总结
「第一次公开演讲」的复盘结论是，关键教训：提前标注停顿点，把「慢下来」写进逐字稿，
下一步：在逐字稿里加停顿标记。

**深度得分：6 / 6**
```

> 注意：纯文本里的 `- 在逐字稿里加停顿标记 | 我 | 2026-02-10 | 高` 被自动拆成了
> 「行动 / 负责人 / 截止时间 / 优先级」四个字段，说明文本格式也能产出结构化行动项。
