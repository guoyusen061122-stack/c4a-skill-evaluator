## 三、迭代记录（共 9 轮，4 次真实 bug 修复）

### 第 1 轮：需求澄清（不是一键生成）

我先让 AI 读挑战资料并总结要求，确认交付物是「5 个命名规范文件 + 一个可执行技能包」。这一步避免了「直接让 AI 生成一堆文件」的敷衍做法。

### 第 2 轮：定架构

确定技能形态为**「脚本驱动 + 指令驱动」双路径**（参考挑战里两个示例技能的两种形态），并敲定报告结构：9 大章节 + 深度自检。

### 第 3 轮：写脚本初版

AI 生成 `aar_report.py` 初版（约 480 行）。我要求：
- 只用 Python 标准库（`json`/`argparse`/`re`/`pathlib`），避免 `pip install yaml` 的依赖负担；
- 支持 JSON + 纯文本两种输入；
- 输出里加「复盘深度自检」自动打分。

### 第 4 轮：写 SKILL.md 和复盘框架

按标准结构写 `SKILL.md`（frontmatter 的 description 里埋了中英文触发短语）+ `references/aar_framework.md`（复盘四问、四象限、5 Why、SMART）。

### 第 5 轮：首次运行 → Bug 1（GBK 编码）

**现象**：`python aar_report.py --sample` 报错 `'gbk' codec can't encode character '\u2705'`。

**诊断**：Windows 控制台默认 GBK，脚本输出的 ✅ emoji 无法编码。

**修复**：在脚本入口强制 `sys.stdout/stderr.reconfigure(encoding="utf-8")`。

**教训**：**跨平台编码问题必须在第一版就处理**，否则换个同学的电脑就崩——这正是「可复用」的红线。

### 第 6 轮：测试文本路径 → Bug 2（漏 import）

**现象**：文本输入路径报 `NameError: name 're' is not defined`。

**诊断**：脚本里用了 `re.split` 但忘了 `import re`（JSON 路径没走到这段，所以之前没暴露）。

**教训**：**每条代码路径都要单独测**，不能只测主路径。

### 第 7 轮：再测文本 → Bug 3（解包错误）

**现象**：`not enough values to unpack (expected 3, got 2)`。

**诊断**：`re.split(r"[:：]", line, maxsplit=1)` 的 `maxsplit=1` 只会返回 2 个元素，我却解包成 3 个变量。

**修复**：改成先取 `parts[0]`/`parts[1]` 的稳健写法。

**教训**：`maxsplit` 语义和字符串 `.split(maxsplit)` 不同，正则 split 的 maxsplit 直接决定元素个数。

### 第 8 轮：检查输出质量 → Bug 4（字段映射缺失）

**现象**：纯文本里的「行动计划」被错误归到「经验教训」，行动项为空。

**诊断**：文本解析器的字段映射表里**漏了 `action_items`**；且行动项的 `| 负责人 | 截止 | 优先级` 格式没有被拆成结构化字段。

**修复**：补上 `行动计划 → action_items` 映射，并新增 `_parse_action()` 把 `|` 分隔的行动项拆成 dict。

**教训**：**新加一种输入格式时，要对照输出逐字段核对**，不能只看「能跑」就以为「对」。

### 第 9 轮：打包 + 文档

打包 `.skill`（zip 格式，与 `materials/` 里两个示例一致），生成样例输入/输出，写齐 5 个交付文档。

## 四、我指挥 AI 的关键 prompt（节选，还原真实指令）

| 轮次 | 我给的指令（大意） |
|------|--------------------|
| 选型 | 「技能要零第三方依赖，只准用 Python 标准库，让不懂代码的人也能用」 |
| 脚本 | 「输入支持 JSON 和纯文本两种，输出固定 9 章结构，最后加一个深度自检自动打分」 |
| 调试 | 「报错 `gbk codec`，是 Windows 编码问题，改成强制 UTF-8」 |
| 验收 | 「纯文本里的行动计划被吃掉了，检查字段映射，行动项要拆成负责人/截止/优先级」 |

**我的指挥方式总结**：不是「一句话让它全做完」，而是**每轮只让它做一件明确的事，做完我验收，发现问题再下一轮**——这也是「多轮迭代」和「prompt 优化」的具体体现。

## 六、对「AI 使用质量」的自我评价

- ✅ **多轮迭代**：9 轮，而非一句话直接提交
- ✅ **prompt 优化**：从「写个脚本」到「零依赖 + 双输入 + 深度自检」逐步细化
- ✅ **工作流设计**：先读资料 → 定架构 → 写核心 → 测试 → 修 bug → 打包 → 写文档
- ✅ **可追溯**：本日志 + 脚本注释 + 4 个真实 bug 的完整记录

**最关键的体会**：C4 的本质不是「交一个技能」，而是「交付一个**别人真能用**的技能」。AI 帮我做的最有价值的事，不是写代码，而是**替我做了一个「陌生人测试」**——它跑一遍、报错、我修，这个过程等价于提前发现「别人拿到手会卡在哪」。
