# AAR 复盘报告生成器（aar-report-generator）

## Purpose

复盘（After Action Review）是「从经历中提炼可复用经验」的关键动作。但大多数人复盘只有一句话感想，
缺少「目标→过程→结果→根因→教训→行动」的完整闭环，导致复盘过后无法指导下一次行动。

本技能把复盘变成一个**结构化、可验证**的过程：

- **输入**：一份复盘记录（JSON 或「标签: 值」纯文本）
- **输出**：一份分章节的 Markdown AAR 报告 + 复盘深度自检

它同时提供两条路径：

1. **脚本驱动**（确定性）：运行 `scripts/aar_report.py`，输入固定格式、输出固定结构。
2. **指令驱动**（灵活性）：不跑脚本，直接按 `references/aar_framework.md` 的框架，用自然语言生成报告。

选择哪条取决于任务性质：需要「精确、可复现」用脚本；需要「灵活润色、结合上下文」用指令。

## Workflow

### Step 1 — 确认输入

先搞清楚用户想复盘的对象是什么，以及手上有没有现成材料：

- 有结构化文件（JSON / 标签文本）→ 走脚本路径（Step 2）
- 只有零散描述、聊天记录、口头叙述 → 走指令路径（Step 3）

### Step 2 — 脚本路径（确定性输出）

```bash
# 用 JSON 输入生成报告，打印到终端
python scripts/aar_report.py 复盘记录.json

# 写入文件
python scripts/aar_report.py 复盘记录.json -o 复盘报告.md

# 生成空白 JSON 模板，方便用户填
python scripts/aar_report.py --template -o 模板.json

# 用内置示例跑一遍，快速看效果
python scripts/aar_report.py --sample
```

脚本零依赖（仅 Python 标准库），Python 3.8+ 即可运行。

### Step 3 — 指令路径（灵活性输出）

如果没有现成文件，按 `references/aar_framework.md` 的框架，引导用户补全信息，再生成报告。
先读取 `references/aar_framework.md` 了解完整框架，然后：

1. 用「复盘四问」引导用户回答问题（预期 / 实际 / 差距 / 下次）
2. 补全「保持·改进·开始·停止」四个清单
3. 追问至少 3 层「为什么」得到根因
4. 把教训转成 SMART 行动项（具体、可衡量、可执行、有时限、有负责人）

### Step 4 — 输出报告

无论哪条路径，报告都按统一结构输出（见下「报告结构」）。最后附上「复盘深度自检」，
明确告诉用户这次复盘覆盖了哪些维度、还缺什么。

## 报告结构（必须完整输出）

```
# AAR 复盘报告：{标题}

## 一、背景与目标（预期是什么）
## 二、实际过程（实际发生了什么）
## 三、结果与差距
## 四、复盘四问（预期 / 实际 / 为什么有差距 / 下次怎么做）
## 五、保持 · 改进 · 开始 · 停止（四象限）
## 六、根因分析（5 Why 追问）
## 七、经验教训（可复制的洞察）
## 八、行动计划（SMART）
## 九、一句话总结
## 复盘深度自检（6 个维度打分）
```

## Edge Cases

- **输入文件不存在**：脚本会报清晰错误，提示用 `--template` 或 `--sample`，不要崩溃。
- **JSON 格式错误**：脚本会指出解析失败位置，并提示修正。
- **纯文本标签无法识别**：忽略无法识别的标签，仅识别已知字段；列表项用 `-` / `*` / `•` 开头。
- **字段缺失**：缺失字段在报告中显示「（未填写）」，并在深度自检中标记为 ❌，而不是报错。
- **表格内容含竖线 `|`**：脚本自动转义，避免破坏 Markdown 表格。
- **行动项没有截止时间/负责人**：深度自检只对「有 action 字段」的项计分，缺失项降级但不报错。
- **用户只有一句话感想**：走指令路径，用复盘四问引导补充，而不是硬凑一份空报告。

## Examples

### 示例 1：脚本路径

输入 `examples/sample_input.json`（或运行 `--sample`），输出见 `examples/sample_output.md`。

### 示例 2：纯文本输入

```text
标题: 第一次公开演讲
日期: 2026-02-01
目标: 讲清楚一个概念，让听众记住一个要点
过程: 准备了一周，写了逐字稿，现场讲了 20 分钟
结果: 现场反响不错，但有 3 个人反馈语速太快
做对了:
- 写了逐字稿，控制了结构
- 提前到场试了设备
需改进:
- 语速太快，重点没停顿
根因:
- 紧张导致赶进度
经验教训:
- 提前标注停顿点，把「慢下来」写进逐字稿
行动计划:
- 在逐字稿里加停顿标记 | 我 | 2026-02-10 | 高
```

运行：

```bash
python scripts/aar_report.py 上面这段文本保存成的文件.txt -o 演讲复盘.md
```

### 示例 3：指令路径（无脚本）

用户说「帮我复盘一下这次考试没考好」，直接按框架提问并生成报告即可，无需脚本。

## Important Principles

- **闭环优先**：一份合格复盘必须回答「预期 → 实际 → 为什么 → 下次怎么办」，缺一不可。
- **要行动不要空话**：教训必须落到「谁、什么时候、做什么」的行动项。
- **诚实归因**：根因要指向自己可改变的因素，而不是外部借口。
- **可验证**：深度自检让复盘质量可被客观打分，而不是凭感觉。
