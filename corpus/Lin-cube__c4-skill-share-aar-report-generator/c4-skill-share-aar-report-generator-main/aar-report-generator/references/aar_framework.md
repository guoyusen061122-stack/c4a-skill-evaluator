# AAR 复盘框架（references）

本文件是 aar-report-generator 技能的参考资料，供指令路径使用：当你需要**不跑脚本、直接用自然语言**生成复盘报告时，按本框架执行。

## 什么是 AAR

AAR（After Action Review，行动后复盘）源自美军，后广泛用于企业和学习场景。核心思想是：**在行动结束后立刻回答四个问题，把经验沉淀成下次可复用的动作**。

## 复盘四问（AAR 核心）

| # | 问题 | 目的 |
|---|------|------|
| 1 | 预期是什么？（What was expected?） | 明确目标与成功标准 |
| 2 | 实际发生了什么？（What actually happened?） | 客观记录，不评判 |
| 3 | 为什么有差距？（Why was there a difference?） | 找根因，不找借口 |
| 4 | 下次怎么做？（What will we do next time?） | 把教训变成行动 |

## 复盘闭环（六段式）

1. **目标**：预期是什么、成功标准是什么（可量化最好）
2. **过程**：实际发生了什么（按时间/关键节点）
3. **结果**：结果如何、与预期差在哪（有数据更好）
4. **归因**：为什么有差距（追问 3 层「为什么」）
5. **教训**：沉淀可复制的经验
6. **行动**：SMART 行动项（谁、做什么、什么时候）

## 保持·改进·开始·停止（四象限）

这是快速提炼行动项的经典工具：

- **保持 Keep**：做对了，继续做
- **改进 Improve**：做了但不够好，优化
- **开始 Start**：没做但该做，启动
- **停止 Stop**：做了但没用/有害，停止

## 根因分析：5 Why

对「结果与预期的差距」连续追问「为什么」，直到找到可行动的根本原因。经验法则：**至少 3 层**，且最终根因要指向「自己可改变的因素」。

```
现象：说明文档没人看
→ 为什么？因为太长
→ 为什么长？因为我什么都想写进去
→ 为什么？因为我不知道读者最需要什么（根因：缺少读者画像）
```

## SMART 行动项

每条行动项都要满足：

- **S**pecific 具体：做什么
- **M**easurable 可衡量：怎么算完成
- **A**chievable 可实现：做得到
- **R**elevant 相关：与目标相关
- **T**ime-bound 有时限：什么时候完成

格式：`{行动} | {负责人} | {截止时间} | {优先级(高/中/低)}`

## 复盘深度自检（6 维度）

一份复盘是否深入，可对照这 6 个维度打分：

| 维度 | 检查点 |
|------|--------|
| 目标明确 | 是否写清「预期是什么」 |
| 过程记录 | 是否记录「实际发生了什么」 |
| 结果量化 | 是否有结果描述（有量化指标更佳） |
| 根因分析 | 是否追问「为什么有差距」 |
| 经验提炼 | 是否沉淀可复制的教训 |
| 行动落地 | 是否有带负责人/截止时间的行动项 |

6 项全中 = 完整闭环；缺 1–2 项 = 基本完整但有缺口；缺 3 项以上 = 复盘信息不足。

## 常见坑

1. **只有结果没有目标**：不知道预期就无法判断「好还是不好」。
2. **只有过程没有归因**：流水账，下次依然犯同样的错。
3. **归因指向外部**：「运气不好」「队友不给力」——这类根因无法指导自己改变。
4. **教训不落地**：有感悟但没有「谁、什么时候、做什么」，等于白复盘。
5. **一次性写完不迭代**：复盘应随反馈更新（v1 → v2 → v3）。
