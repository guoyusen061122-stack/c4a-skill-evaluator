## 2. 做对了什么

1. **选题对准真实痛点**：技能解决的是「课程提交前反复被打回」的机械问题 —— 命名、缺件、空文件。这是同伴**当下就会用到**的东西，天然具备传播动机。
2. **确定性设计**：同目录同输入永远同输出，且只依赖标准库 —— 换台机器、断网也能跑，降低了别人用的门槛。
3. **规则不猜**：C1/C2 规则来自平台实测返回，C4 规则引 `CHALLENGE.md` 具体行号，C3/C5–C7 直接标注未收录并明说「不做齐全性判定」。
4. **文档分层**：`SKILL.md` 面向 AI 执行，`skill说明` 面向「这是什么」，`教学说明` 面向「怎么上手」—— 三类读者分开写。

## 4. 如果重来一次

1. **先定接口再写实现**：`--dir / --challenge / --name` 三个参数在第 1 轮就定死，后面改的都是内部实现 —— 这个顺序值得保持。
2. **每轮都跑真实命令**：崩溃那次就是因为「读代码觉得没问题」。此后每轮以真实退出码为准 —— 这条最值钱。
3. **打包纳入常规验证**：把「打包 → 解包核对成员体积」做成固定动作，避免包内是旧版本。
4. **早一点做 demo**：demo 是必交项却最后才补，导致多跑一轮预检。
