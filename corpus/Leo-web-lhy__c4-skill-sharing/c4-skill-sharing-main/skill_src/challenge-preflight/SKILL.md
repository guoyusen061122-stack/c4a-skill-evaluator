# 挑战交付物预检器（challenge-preflight）

一句话：**在点「提交」之前，用一条命令把交付目录自查一遍——把"被打回"的三类机械原因（命名不对、缺件、占位符没删）挡在提交门外。**

## 1. 它解决什么问题

课程挑战被打回，多数不是内容不行，而是机械问题：

| 被打回的原因 | 后果 | 预检怎么发现 |
| --- | --- | --- |
| 文件名不符合规范（`AI日志.md` 写成 `ai-log.md`） | 平台按文件名匹配必交项，直接判「缺件」 | 用该挑战的必交规则逐条正则匹配 |
| 少交一个文件（忘了 demo 截图 / 忘了 AAR） | 产物完整性扣分 | 逐条列出「已匹配 / 未匹配」 |
| 正文里还留着「待补充」「XXX」「TODO」 | 评审一眼看到，判为未完成 | 全目录占位符扫描 |
| 空文件（建了没写内容） | 等于没交 | 扫 0 字节文件 |
| 把 `.git`、`.scratch`、`node_modules` 一起交上去 | 体积爆炸、泄露临时文件 | 杂物清单 |

**边界很明确**：它只做机械检查，**不判断内容好不好**。内容质量归你和评审，机械问题归它。

## 2. 什么时候用

- 用户说：「提交前检查一下」「预检」「交付物齐了吗」「这个挑战能交了吗」
- AI 准备调用平台的 `check-deliverables` / `prepare-submission` / 提交接口之前 —— **先跑预检，再谈提交**。

## 3. 输入 / 输出

| | 内容 |
| --- | --- |
| 输入 | `--dir` 交付目录（必填）、`--challenge` 挑战编号 C1–C7（必填）、`--name` 姓名前缀（可选） |
| 输出 | Markdown 报告（默认）或 JSON（`--json`）；退出码 `0`=PASS、`1`=FAIL、`2`=参数/环境错误 |

退出码让它可以被脚本直接串起来：`python preflight.py ... && 提交`。

## 4. 使用步骤

1. **定位目录**：找到交付物所在目录（就是你要上传的那一层，不要指到里面一层去）。
2. **运行**：
   ```bash
   python scripts/preflight.py --dir "<交付目录>" --challenge C4 --name 阮如意
   ```
3. **读结论**：第一行就是 `PASS` / `FAIL`。FAIL 只看两件事——**缺件**和**空文件**。
4. **修行动项**：报告末尾的「行动项」逐条改。
5. **复查**：改完再跑一次，直到 PASS。（同一目录重复运行结果完全一致，可放心反复跑。）

## 5. 七类检查

| # | 检查 | 级别 | 说明 |
| --- | --- | --- | --- |
| 1 | 结论 | — | 依据 2、3 汇总 |
| 2 | 必交项齐全性 | **FAIL** | 逐条规则匹配（含排除规则，避免"教学说明"冒充"可执行内容"） |
| 3 | 空文件 | **FAIL** | 0 字节文件 |
| 4 | 占位符残留 | WARN | 关键词命中，附 `文件:行号: 片段` |
| 5 | 命名 / 姓名前缀 | WARN | 未给 `--name` 时从文件名自动推断 |
| 6 | 杂物 | WARN | `.git`、`.scratch`、`node_modules`、`Thumbs.db`… |
| 7 | 体量统计 | INFO | 文件数、总体积、逐个大小（前 20） |

## 6. 规则来源（诚实声明）

规则在 `references/rules.json`，**每条都带 `source`**：

- **C1 / C2**：来自平台 `prepare-submission` 实测返回的必交清单（真实跑出来的，不是猜的）。
- **C4**：来自 `CHALLENGE.md` 第四节命名表（第 44–50 行）与上传清单（第 292–298 行）。
- **C3 / C5 / C6 / C7**：`"verified": false` —— 未收录。此时脚本只做通用检查，并在报告里明写「该挑战的必交规则未收录，未做齐全性判定」。

> 设计原则：**不知道就说不知道**。宁可少检查一项，也不编一条规则让使用者误判。

要支持新挑战：在 `rules.json` 的 `challenges` 下加一项，`include` 写正则数组、`min` 写最少命中数，`namePrefixed: true` 表示文件名必须带姓名前缀。

## 7. 边界情况（都实测过）

- **目录不存在** → 退出码 2，报错不崩。
- **目录为空** → 所有规则判缺件，FAIL。
- **文件名含中文 / 空格** → 正常，正则按 UTF-8 处理。
- **超大文件** → 占位符扫描自动跳过（默认 >3 MB），仍然计入体量统计。
- **二进制文件 / 图片** → 不做占位符扫描，只统计大小。
- **姓名没给** → 从 `*_C4_*` 文件名里取最高频前缀作为推断值，并标注「推断」。
- **同一文件命中多条规则** → 各自独立计数，不会互相抵消。
- **关键词自我命中** → 规则表 `rules.json` 与 `SKILL.md` 本身就包含占位词表，扫自己必然命中。用规则里的 `ignorePaths`（或命令行 `--ignore`）排除这类路径；C4 规则已内置 `ignorePaths: ["skill_src/**"]`。

## 8. 局限（请务必知道）

1. **只查机械问题，不查内容质量**。PASS ≠ 内容优秀。
2. **规则表是快照**：课程方改了命名规范，`rules.json` 要同步更新（`source` 字段就是给你核对用的）。
3. **占位符扫描可能误报**：正文里正当地讨论"待补充机制"也会被标出——所以它是 WARN，需要你人眼确认。
4. **不联网**：不校验仓库链接是否可访问、不校验平台侧状态。那两步用平台的 `check-deliverables` / `prepare-submission`。

## 10. 与平台工具的分工（别用错）

| 工具 | 联网 | 查什么 | 什么时候用 |
| --- | --- | --- | --- |
| **本技能** `preflight.py` | ❌ 离线 | 命名、缺件、空文件、占位符、杂物、体量 | **每次提交前**，随时可跑，零依赖 |
| 平台 `check-deliverables` | ✅ | 平台侧口径的必交项 | 想核对"平台认不认"时 |
| 平台 `prepare-submission` | ✅ | 提交就绪度 + `actionItems` | 真正准备提交那一次 |

推荐顺序：**本技能（先把机械问题清零） → `prepare-submission`（再对平台口径）。**
本技能的价值就是"离线、免费、想跑多少次跑多少次"，不必为了查一个文件名去联网。

## 11. 一个真实例子（可复现）

```bash
$ python scripts/preflight.py --dir "./C4" --challenge C4 --name 阮如意
结论：FAIL —— 缺 1 项必交、0 个空文件
必交项：
  ✅ Skill 说明文档      阮如意_C4_skill说明.md
  ✅ 可执行内容          阮如意_C4_challenge-preflight.skill
  ❌ Demo（截图或视频）  未找到
  ✅ 教学说明            阮如意_C4_教学说明.md
  ✅ AI 日志             阮如意_C4_AI日志.md
行动项：
  1. [FAIL] 补齐「Demo」：加一张 阮如意_C4_demo截图.png
（退出码 1）
```

补上截图后再跑一次 → `结论：PASS`（退出码 0）。**这就是它的全部用法。**

## 12. 目录结构

```
challenge-preflight/
├── SKILL.md                 # 本文件（第 2 层：加载正文）
├── scripts/
│   └── preflight.py         # 可执行主体（纯标准库，Python 3.9+）
└── references/
    └── rules.json           # 规则表（第 3 层：按需加载，每条带 source）
```

安装后触发方式：`"提交前预检"` / `"交付物齐了吗"` / `"检查 C4 能不能交"`。
