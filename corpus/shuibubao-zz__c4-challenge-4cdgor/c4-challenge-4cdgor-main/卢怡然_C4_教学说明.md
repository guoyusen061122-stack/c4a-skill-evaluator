# challenge-submit-guard 教学说明

> 面向完全没用过这个技能的人。**目标：3 分钟从零到跑出第一份报告。**
> 交付人：卢怡然 ｜ C4 技能分享与传播

---

## 零、先说清楚它是干什么的

它是一个**命令行体检器**。你给它一个文件夹，它对照平台 rubric 告诉你：

> 你这个挑战的交付包，还缺什么？会不会踩红线？最可能在哪丢分？

**它不是评分器。** 它说"粗估 90 分"不代表你真能拿 90 分（我自己 C3 实测：粗估 90，平台实评 77）。
它的价值在于**指向**——告诉你去哪补，而不是告诉你得几分。

## 一、3 分钟上手

### 第 1 步：拿到文件（30 秒）

从 `卢怡然_C4_challenge-submit-guard.skill` 里解压出 `challenge-submit-guard/` 文件夹，
**放在哪都行**。或者直接用仓库里的 `challenge-submit-guard/` 源码目录。

> `.skill` 文件本质是 ZIP，改后缀名或用解压软件都能打开。

### 第 2 步：确认能跑（10 秒）

```bash
cd challenge-submit-guard/scripts
python challenge_submit_guard.py --self-test
```

看到这个就成了：

```
  ✅ PASS  完整交付包 → 5 项必交物全命中、无红线
  ✅ PASS  空文件夹 → 命中缺失+无日志红线，产物完整性被封顶
  ✅ PASS  一句话 AI日志 → 命中 one_shot_ai，AI使用维度被封顶
  ✅ PASS  不传 -c → 从文件名自动识别挑战号
  ✅ PASS  注册表完整性 → 每个挑战都有交付物与维度定义

自检结果：5 通过 / 0 失败
```

**只要有一个 ❌，先别往下走**——说明环境或文件有问题（见第四节"常见坑"）。

### 第 3 步：跑你的第一个体检（10 秒）

```bash
python challenge_submit_guard.py "C:/你的/交付/文件夹"
```

不写 `-c` 也行，它会自动从文件夹名或文件名里认挑战号。

想指定：
```bash
python challenge_submit_guard.py "C:/你的/交付/文件夹" -c C4
```

不确定编号有哪些：
```bash
python challenge_submit_guard.py --list
```

### 第 4 步：读懂报告（2 分钟）

报告 7 节，按这个顺序看：

| 先看 | 节 | 看到什么就动手 |
|---|---|---|
| ① | **3 红线扫描** | 有 🚩 **立刻停**，先把红线解了 |
| ② | **1 交付物核对** | 有 ❌ 就补那个文件 |
| ③ | **5 提分杠杆** | 时间只够改一处，改第 1 条 |
| ④ | **6 TODO** | 按顺序做 |
| ⑤ | **7 人工确认** | 提交前自己打勾 |

## 二、三种典型用法

**用法 A：提交前最后一道关**（最常见）

```bash
python challenge_submit_guard.py ./C4 -c C4
```

**用法 B：存档 / 给 AI 读**

```bash
python challenge_submit_guard.py ./C4 --out 体检报告.md
python challenge_submit_guard.py ./C4 --json > audit.json   # 程序可读
```

**用法 C：当门禁（提交前自动拦）**

```bash
python challenge_submit_guard.py ./C4 -c C4 --strict || echo "还不能提交，见上面红线"
```

`--strict` 下：缺必交物或命中红线 → 退出码 1；否则 0。

## 三、红线是怎么判的（重要，别踩）

| 红线 | 触发条件 | 后果 |
|---|---|---|
| `missing_artifacts` | 任一**必交物**缺失 | 产物完整性维度 ≤ 5 分 |
| `no_ai_log` | 找不到 AI日志，或有效内容 **< 800 字** | 复盘质量维度 ≤ 5 分 |
| `one_shot_ai` | AI日志 **< 400 字**，或里面没有迭代痕迹 | AI使用质量维度 ≤ 5 分 |
| `empty_files` | 存在 0 字节文件 | 提示（不封顶，但空文件算没交） |

**"迭代痕迹"指什么？** 日志里出现这些词之一：
迭代、轮、v2、v3、prompt、提示词、修改、优化、改进、反馈、失败、报错、重试、回滚、调整、重做、评审、初评。

也就是说，AI日志里**必须写清楚**：第几轮、改了什么 prompt、哪次失败了、你怎么改的。
只写"我用 AI 写完了"→ 直接判 `one_shot_ai`。

## 四、常见坑（按我踩的顺序排）

### 坑 1：`.skill` 是 ZIP，不是 tar.gz

CHALLENGE.md 里写"打包后的 `.skill` 文件就是一个 tar.gz 压缩包"。
**实测不对** —— 平台附带的 `wechat-doc-mapper.skill` 和 `skill-explainer.skill`
都是 `PK` 开头的 **ZIP** 文件。用 `tar -xzf` 解会报 `not a gzip file`。

✅ 正确做法：按 ZIP 解（改后缀 / 解压软件 / `zipfile`）。
`scripts/pack_skill.py` 就是按 ZIP 打包的，结构和平台示例一致。

### 坑 2：Git Bash 里用 `C:/` 路径调用 Python 会失败

```bash
tar -tzf "C:/Users/xxx/a.skill"   # ❌ Cannot connect to C: resolve failed
```

Windows 的 Python 不认 Git Bash 的 `/c/...` 映射。

✅ 正确做法：脚本里用 `C:\Users\...` 反斜杠原生路径，或先 `cd` 到目标目录。

### 坑 3：文件夹名小写会认不出挑战号

我把自己的 C1 文件夹命名为 `c1`（小写），早期版本识别失败直接退出。

✅ 已修：v4 起大小写不敏感。`c1`、`C1`、`c1_translate` 都能认出来。

### 坑 4：交付物"存在"但其实是空文件

新建了一个 `demo.png` 占位、还没填内容 → 脚本判 **⚠️ 空文件**，**不算已交**。

✅ 这是故意的。别用空文件凑数。

### 坑 5：以为粗估分就是最终分

见第零节：我 C3 粗估 90，平台实评 77。

✅ 正确用法：把粗估当**雷达**，不当**分数**。必看报告第 7 节。

### 坑 6：没装 PyYAML 以为会报错

不会。内置了迷你 YAML 解析器，装了 PyYAML 就用 PyYAML，没装就用内置的，功能一致。

## 五、进阶：改规则不用改代码

所有判定规则在 `challenge-submit-guard/references/challenges.yaml`：

```yaml
  C4:
    title: "C4 技能分享与传播"
    deliverables:
      - label: "skill说明"
        pattern: "*skill说明*"
        required: true
    dimensions: [...]
    red_flags:
      - id: "missing_artifacts"
        cap: 5
```

- 想加你自己学校的挑战 → 在 YAML 里加一段，**代码一行不用动**
- 想放宽 AI日志 字数阈值 → 改脚本顶部的 `MIN_AI_LOG_CHARS`（默认 800）
- 平台更新了 rubric → 重跑生成器，自动同步：

```bash
python scripts/build_registry.py --source "C:/你的/挑战资料/父目录"
```

它会扫描所有 `挑战_*_完整资料/` 目录里的 `challenge.json` + `rubric.json`，重建 YAML。
**注册表不是手打的，所以不会手滑。**

## 六、优化技巧

**技巧 1：把自检接到提交流程里**

每次 `git commit` 前跑一次 `--strict`，红线没清零就不许提交。

**技巧 2：用命名规范倒逼整洁**

只要文件都叫 `姓名_C4_部件.ext`，脚本的第 2 节会显示"0 个不符合"，
而且 `-c` 可以省略（自动识别）。一次命名，长期省事。

**技巧 3：AI日志 边做边写，别最后补**

最后补的日志必然踩 `one_shot_ai`（因为没有迭代痕迹可写）。
正确做法是每轮改完就记一行：改了什么、为什么改、效果如何。

**技巧 4：把 `--json` 接给 AI**

```bash
python challenge_submit_guard.py ./C4 --json > audit.json
```
然后把 `audit.json` 丢给 AI 说"按 TODO 顺序帮我补"，比你自己读 Markdown 快。
