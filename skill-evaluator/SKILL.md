# c4a-evaluator —— C4 技能提交自动评审器

## 一句话

**输入**一个包含若干 C4 技能提交的目录（或单个仓库），
**输出**每位作者的完整性矩阵、四条件得分、红旗清单与改进建议，
以及一份班级总览（Markdown / CSV / HTML / JSON）。

## 它解决什么问题

C4 每人交五个文件，一个班几十人。人工核对"谁缺了什么"要几十分钟，
而且**没有统一标准**：同样一份提交，两个人看可能给出不同结论。

本技能把这件事变成**可复现的机械流程**，并且**每一分都带 `文件:行号` 证据**，
所以结论可以被人工复核，而不是"我觉得这份不太好"。

## 与"数关键词"的本质区别

一个只会数关键词的评审器**可以被三个动作骗到**，本技能对每一个都有对应防线：

| 骗法 | 朴素评审器 | 本技能 |
|---|---|---|
| 文件名全对、内容全空 | 完整性 5/5 | 空文件不参与槽位匹配 → 完整性低 + `empty_deliverable` 红旗 |
| 正文堆满规则词 | 质量分接近满分 | 结构项/信号比值 < 0.55 → `keyword_stuffing`，封顶 60 |
| 写「本项目**没有**测试」 | 命中「测试」→ 判为有测试 | 否定语境闸门（命中点前 8 字符内有否定词即作废） |

这不是设计口号，是 `tests/` 里可跑的对照实验 —— 同一批样本上，
朴素评审器有 2/18 落到人工标注区间之外，本技能 18/18。

## 工作流

### Step 1 — 扫描与作者归因

递归扫描目录。作者按四条规则提取，**分不清就不归**：

1. 文件名前缀 `姓名_C4_` → 该作者（最高置信）
2. 位于资料目录（挑战正文 / scripts / references / assets / run / output…）→ **不算提交**
3. 根目录下没有前缀的文件（README.md、LICENSE）→ **不算交付物**
4. 其余：若全仓库只有一个已知作者 → 并给他；否则 → `_未识别_`，**单独列出、不排名**

> 为什么不用"最近的父目录一律当作者"：实测会造出 `challenge-preflight`（技能名）、
> `c4-skill-sharing-main`（zip 包装目录）、`skill-run` 三个幽灵作者，班级人数从 1 变 4。

### Step 2 — 交付物槽位匹配

C4 的五个必交文件。一个文件可能同时像"教学说明"和"Skill 说明"，
所以做**全局最优匹配**（穷举 5 槽位 × 前 8 候选），每个文件只归一个槽位。

> 朴素做法是每个槽位各自挑最高分文件 → 同一个文件被记两次，完整性虚高。
> 先试贪心：`张三_C4_skill说明.md` 对 `skill_doc` 和 `executable` 都 8 分，
> 贪心让 `executable` 先挑，抢走说明文档，真正的代码没人要 → 完整性 5/5 掉到 4/5。

### Step 3 — 四条件质量评分

每条检查都有 `id`、权重与证据。核心检查是**锚点**：锚点不过则整个条件封顶 0.5
（缺了「输入X输出Y」这句话，「IO 明确」这一个条件就不算达成）。

| 条件 | 检查项 | 锚点 |
|---|---|---|
| 可复用 | 6 项（安装说明 / 无硬编码路径 / 无密钥 / 依赖 / 平台 / 可复制示例） | R1 |
| 可执行 | 6 项（代码或技能包 / frontmatter / 入口 / 分步工作流 / 可编译 / 边界） | E1 |
| 可验证 | 5 项（测试 / 预期输出 / 判定标准 / Demo 真实性 / 断言） | V1 |
| IO 明确 | 4 项（一句话 IO / 输入格式 / 输出格式 / 输入不合法时怎么办） | I1 |

### Step 4 — 红旗与封顶

红旗不是装饰：**每条红旗都给复合分设上限**。缺 1 个交付物上限 75，
缺 3 个以上上限 45；交付物是空文件上限 60（按空文件数量分级）；
关键词堆砌 60；明文密钥 50。

### Step 5 — 出报告

Markdown（人读）+ CSV（表格处理）+ HTML（仪表板，可直接截图）+ JSON（机器读）。

## 运行

```bash
# 单个目录
python c4a_evaluator.py <目录>

# 指定输出与格式
python c4a_evaluator.py <目录> --out review_output --format md,csv,html,json

# 确定性模式（输出不含时间戳，便于做哈希一致性断言）
python c4a_evaluator.py <目录> --deterministic
```

退出码：`0` 成功 / `2` 路径不是目录 / `3` 目录里没找到任何文件。

## 边界情况

| 情况 | 处理 |
|---|---|
| 空目录 | 报"未找到任何文件"并返回退出码 3，**不假装评了 0 分** |
| 文件名不含 `姓名_C4_` 前缀 | 回收退到"仓库级提交"；多作者时标 `_未识别_` 且不排名 |
| 空文件 / 占位符 | 空文件不进槽位；`占位.md`、`.gitkeep` 这类**有意的**空文件不报警 |
| 同一作者多版本 `_v1/_v2` | 只占一个槽位，不会同时算成两个交付物 |
| GBK 编码 | UTF-8 → GB18030 → Big5 逐级回退 |
| `.skill` 包 | 当作 tar.gz 解开，成员文本参与匹配与 frontmatter 检查 |
| `.docx` | 用 zipfile + XML 抽正文（不需要 python-docx） |
| `.pdf` | 只做文件名匹配（无第三方库时无法解析正文，已如实标注） |
| 超大文件（>2 MB） | 跳过内容分析，仅文件名/类型匹配 |
| Python 语法错误 | E5 不通过 + `syntax_error` 红旗（上限 85） |

## 说明

- **只有规则层。** 规则层判"有没有、够不够结构"，**不判内容好不好**。
  内容质量需要 LLM 复核层，协议见 `references/llm_review_protocol.md`。
  **没有复核层的结论不应被当作最终评分。**
- **传播证据只报状态、不折算分数。** C4 把"被使用次数"列为最高权重，
  但仓库里没有使用回执 ≠ 没被用过（群里用了不会留下文件）。
  把"找不到证据"直接判 0 分是不诚实的。
- 规则全部在 `references/c4_rubric.json`，改规则不需要改代码。
