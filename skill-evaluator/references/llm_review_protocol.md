# LLM 复核层协议（可选，规则层之外的第二步）

> **本层未被运行过。** 本环境没有任何模型 API 凭据，所以本仓库里
> **没有任何来自真实 LLM 的复核结果**。这个文件交付的是一个**可执行的协议**，
> 而不是一堆看起来很专业的"AI 评审意见"。
>
> 这一点必须写在最前面：一份声称"规则 + LLM 双引擎"、
> 但 LLM 那一半从未真正跑过的提交，比一份诚实地只做规则层的提交更糟。

---

## 为什么规则层不够

规则层能回答的：

- 五个交付物齐不齐？
- 有没有安装说明、有没有测试、有没有「输入X输出Y」？
- 结构够不够（有没有标题层级、代码块、分步流程）？

规则层**回答不了**的：

- 那份 `skill说明.md` 说的是真事还是套话？
- 示例是真的运行过，还是编的？
- 这个技能真的解决了它声称要解决的问题吗？
- 改进建议里哪一条最值得先做？

这些需要读懂内容，也就是需要 LLM。

## 协议设计：三条硬规则

### 规则 1 — LLM 只能**在规则层给分的基础上做有界调整**

```
final = clamp(rule_score + Δ, rule_score − 0.15, rule_score + 0.15)
```

LLM 不能推翻规则层。理由：规则层是**确定、可复现、可复核**的；
LLM 是**随机、不可复现**的。如果 LLM 能推翻它，整个评审器的可复现性就没了 ——
同一个文件夹今天给 0.8、明天给 0.6，分数就失去了可比性。

±0.15 的带宽表示"LLM 可以纠正规则层的误判，但不能凭自己的偏好重排全班"。

### 规则 2 — 每一次调整必须附**可核对的具体证据**

不允许出现"整体质量一般"这类无锚点的判断。必须形如：

```json
{"dimension": "verifiable", "delta": -0.10,
 "evidence": "SunYi_C4_教学说明.md:23 声称'实测输出如下'，但紧接的代码块里是
              占位文本 <your output here>，不是真实运行结果",
 "rule_layer_was_wrong_because": "V2 只匹配了'实测'这个关键词，没有检查后面的内容"}
```

`rule_layer_was_wrong_because` 是必填字段。**填不出来就说明规则层没错，不该调整。**

### 规则 3 — LLM 与规则层不一致时**记录下来**，不要静默平均

```
若 |Δ| ≥ 0.10：该条写入 disagreements[]，在报告里单独列出
```

分歧本身就是信息 —— 它指出了规则层的边界。例如：
一个提交写得很好但格式不标准，规则层扣分、LLM 加分，
这个分歧提示"格式权重是否过高"。静默平均会把这个信号抹掉。

## Prompt 模板

```
你是 C4「技能分享与传播」提交的复核评审员。规则层已经给出了一份机械评分，
你的任务是**在规则层的基础上做有界修正**，而不是重新打分。

【规则层结论】
作者：{author}
完整性：{present}/{required}    缺失：{missing}
四条件得分：{condition_scores}
规则层命中/未命中的检查项：{checks}
规则层给出的证据：{evidence}
规则层红旗：{red_flags}

【提交内容摘录】
{content_excerpt}

【任务】
只在你能指出**规则层判断错误的具体位置**时才调整分数，调整幅度不超过 ±0.15。
对每一条调整，必须给出：
  · dimension（四个条件之一）
  · delta（−0.15 ~ +0.15）
  · evidence（文件名:行号 + 原文片段）
  · rule_layer_was_wrong_because（规则层为什么错了）

如果规则层没有明显误判，就返回空数组 —— **不要为了显得"我干了活"而强行找问题。**

另外回答两个规则层答不了的问题：
  1. 这份技能解决了它声称要解决的问题吗？（一句话）
  2. 如果只能提一条改进建议，是哪一条？

只输出 JSON，不要别的文字。
```

## 输出 schema

见 `llm_review_schema.json`。要点：

- `adjustments[]`：每条必须带 `evidence` 与 `rule_layer_was_wrong_because`
- `summary`：一句话说明这份技能是否真的解决了它声称的问题
- `top_suggestion`：只允许一条
- `confidence`：`high` / `medium` / `low`，`low` 时合并权重减半

---

## 合并规则（规则层 + LLM 层）

```
对每个条件：
    base = rule_condition_score
    Δ    = Σ(该条件下所有 adjustments 的 delta)
    Δ    = clamp(Δ, −0.15, +0.15)
    final = clamp(base + Δ × confidence_weight, 0, 1)

复合分照旧 = 完整性 × 0.4 + 质量 × 0.6，然后**再套红旗上限**。
```

注意顺序：**红旗上限在最后**。LLM 不能把带了空交付物红旗的提交捞回高分。

## 如何运行（需要凭据时）

```bash
# 任何 OpenAI 兼容端点
export OPENAI_API_KEY=...
export OPENAI_BASE_URL=https://api.openai.com/v1
python scripts/llm_review.py --payload review_output/评审结果.json \
       --out review_output/llm_review.json --model gpt-4o-mini
```

无凭据时脚本会**明确报错退出**，而不是返回一个伪造的空结果 ——
"没跑"和"跑了但没发现"必须在输出上可区分。
